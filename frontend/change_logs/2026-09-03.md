2026-09-03 frontend
========================================

**No frontend code changed today.** The whole day was backend, and this file exists so that
whoever picks it up next knows what moved underneath it.


## What changed underneath
------------------------------

Three of today's backend changes reach the api the front end talks to. None of them was verified
against a running front end -- that is the first thing to do next time.

### The delete endpoint lost a parameter and gained one

`DELETE /v2/crawl/{idOrName}/versions`

| Parameter | Was | Now |
|---|---|---|
| `before` | remove every version below this | **gone** |
| `keepLatest` | keep this many newest | unchanged |
| `version` | one version | unchanged |
| `purge` | — | **new**: true drops the catalog's index rather than emptying it |

Naming no version at all now means the whole catalog: emptied by default, and with `purge=true`
the index is dropped as well. A grep of `frontend/src` found nothing sending `before`, so this is
probably already fine -- but a grep is not a run.

### The catalog json is the same shape, with one field renamed underneath

`extractor` is an enum now (`adaptive | restclient | htmlunit | playwright | selenium`) rather than
free text. **The json is unchanged** -- still the same string under the same key -- but an unknown
value is now refused with a 400 instead of being stored and failing later. A form that offers a
free text box for it should offer a select.

Timestamps were standardised on every table: `created_at` and `updated_at` everywhere. The catalog's
`lastModified` is now `updatedAt`, and `lastIndexed` stayed. Search results keep `createTime`; that
is a document field, not a column, and nothing changed there.

### Search may be answered by a different engine

The index and the vector store are now embedded (Lucene) by default rather than Elasticsearch and
Qdrant. The api, the request and the response are identical -- same fields, same cursor, same
highlighting -- so nothing should notice. Two things a page might be showing that are worth a look:
anything that names Elasticsearch or Qdrant in the ui, and the cluster page, which reads the
spreader actuator endpoints and is unaffected.


### Deleting a version also clears the crawler's working state

The delete endpoint's `db` layer now removes the version's frontier and dedup stores along with
its rows. No api change -- same request, same response -- but the `bytes` figure on the `db` line
of the delete report is no longer always zero.


### The front end is now its own container, behind one address

`./run-docker.sh -n 3` starts `greenfinger-web` alongside the nodes: nginx, this build, and the
api proxied through. **Open http://localhost:50079** (`--web-port` changes it, `--no-web` skips
it). The nodes still serve the app on their own ports, so nothing that worked before stopped.

Two things had to be fixed before signing in worked through it, and both looked like a wrong
password in the browser:

1. **403 `Invalid CORS request`.** The page comes from the front end container, so the browser
   sends `Origin: http://localhost:50079`, and the node only knew about `http://localhost:4200`.
   The nodes are now told the front end's real origin.
2. **`Sign in first` on the request after signing in.** A token lives in the memory of the node
   that issued it, so a request balanced onto another node is not authenticated. The proxy is
   failover rather than balancing until that changes.

Neither needed a front end change. Worth knowing when running the app against a cluster: a signed
in session is tied to one node, and if that node goes away the sign-in goes with it.

### `layers=` accepts `+`

`POST /v2/crawl/{id}/replay?layers=` and the delete endpoint's `layers` documented `+` and only
accepted commas. Both forms work now.
