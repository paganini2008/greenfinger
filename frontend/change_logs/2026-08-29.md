## 二、接手前需要知道的

### 1. 后端会以什么形态提供接口

后端已经打包成 **`greenfinger-spring-boot-starter`**（Maven 制品名沿用 1.x），
就是为了将来嵌进一个 Spring Boot 接口项目、给前端提供 REST API。

自动装配已提供这些 bean，写 Controller 时直接注入即可：

| Bean | 用途 |
|---|---|
| `CrawlerLauncher` | 发起抓取，可传回调拿到实时 `Dashboard` |
| `CatalogStore` / `CatalogAdminService` | catalog 的增删改查、清理、版本升级 |
| `CrawlRegistry` | 哪些在跑、中断、取实时或最终统计 |
| `ManifestReplayer` | 把本地抓取结果重放进 ES / 向量库 |
| `ElasticsearchSearcher` | 关键词检索，返回带 `<em>` 标记的高亮片段 |

> **注意**：目前后端**没有 REST 层**，只有 CLI。做前端时需要先补一个 web 模块。

### 2. 1.x 界面有哪些功能（新界面至少要覆盖）

老界面的截图在根 `README.md` 里（p1–p6），源码在 `history/greenfinger-ui/`。
功能面已在后端全部实现，对应关系：

| 1.x 界面 | 后端现有能力 |
|---|---|
| Catalog 列表（分页、运行状态图标） | `CatalogStore.findAll()` + `CrawlRegistry.isRunning()` |
| 新建 / 编辑 Catalog | `CatalogAdminService.save()`，只有 url 必填，其余自动补默认值 |
| 行操作：Clean / Crawl / Rebuild / Summary / Interrupt / Sync / Upgrade | 全部有对应命令与服务方法 |
| Monitor 面板：剩余时间、进度条、URL 分布饼图、资源柱状图、Catalog 明细 | `Dashboard` 接口提供全部计数器 + `getProgress()` / `getRemainingTime()` |
| Query 页：关键词 + 分类过滤 + 分页 + **高亮** | `ElasticsearchSearcher`，`SearchResult.highlights` 已带标记 |
| 登录 / 登出 | **未实现**，1.x 有 `LoginController` + `WebSecurityConfig`，需要时再补 |

### 3. 新界面比 1.x 多出来的东西

后端新增了这些，界面上需要有位置：

- **三条输出路径**单选（local / elasticsearch / vector），取代 1.x 的 `indexed` 复选框
- **图片**：每页的图片数量、缩略图、图片总数统计
- **内容去重命中数**（新计数器 `duplicatedContentCount`）
- **断点续爬**：显示 frontier 剩余条数，提供 resume 按钮
- **replay**：从本地结果重放进 ES / 向量库
- **blob 存储**选择（local / minio）
