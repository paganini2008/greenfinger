## 1. 暗色主题

改动比预想的小，因为上一轮所有颜色都走了 `--mat-sys-*`：

```scss
html { color-scheme: light dark; }          // 之前是 light
html[data-theme='light'] { color-scheme: light; }
html[data-theme='dark']  { color-scheme: dark; }
```

`mat.theme()` 生成的 token 本来就是 `light-dark()` 对，由 `color-scheme` 决定取哪一半。
所以**整个主题切换就是这一个属性**，`ThemeService` 里一个颜色值都没有。

三档而不是两档：system / light / dark，一个按钮循环。默认 system —— 跟随操作系统是大多数人
已经做过的选择，再问一次没有意义。图标显示的是"按下去会变成什么"，这是三态开关的读法。

**存 localStorage，不存账号**。主题是"我面前这块屏幕"的属性，不是"我是谁"的属性；
运维机器换班时不该跟着换外观。

**防闪**：`index.html` 里一小段脚本在 Angular 启动前读同一个 key 打上属性。否则选了暗色的人
每次刷新都会先看到一下白色。脚本只做这一件事，之后全归 `ThemeService`。

四处写死的颜色改成 `light-dark()`：index / vector 两种 chip 的蓝紫是固定色相
（它们表达的是"索引"和"向量"，不是主题色），暗底上原来的深蓝深紫看不清。
hero 上的白点没动 —— hero 永远是绿的，白在两个主题下都对。

## 2. 语义 / 图片检索翻页

服务端加了 `offset` 参数，前端接上。

**为什么不是 cursor**：关键词检索走 cursor 是因为 ES 有稳定排序键可以往下传；向量检索的顺序是
"到这条查询的距离"，只对这一次查询存在，没有可以携带的东西。所以是 offset，也因此有上限
（服务端 1000）——offset 越深向量库走得越久，翻到那么深不如换个查询。

- 拿满一页就认为还有下一页，不足就没有（向量检索答的是"最近的 n 条"，不存在"一共多少条"）
- `moreHits()` 同时看上限，所以是**在服务端说不之前就不再提供**，而不是让人点了才被拒绝
- 每页 12（语义）/ 24（图片）—— 一屏的量，图片小所以能放两倍

## 3. e2e

`@playwright/test`，6 个用例，`npm run e2e`（对着 `GF_E2E_URL`，默认 `http://localhost:8088`）。

配置里**故意没有 `webServer`**：从这里启动 jar，就等于让这份配置也管数据库、爬取目录和端口，
那三样里任何一样出问题都会被报告成"测试失败"。服务端自己起，这里只负责测。

覆盖的是单测覆盖不到的那一类问题 —— 每个部件都对，但部件之间不再互相认识：

| 用例 | 盯的是 |
|---|---|
| 未登录访问 `/catalogs` | 跳登录页，且**没有外壳** |
| 密码错 | 留在表单上报错，不跳转 |
| tester 登录 | 看不到 New catalog，看得到"只读"说明 |
| 版本徽章 | 来自服务端而不是写死 |
| 主题 | 切到 dark，刷新后还是 dark |
| 主链路 | 登录 → 建 catalog → Crawl → Monitor 显示计数 → 删除 |

主链路那条**真的建 catalog、真的爬**（max fetch size 1、duration 1），catalog 名带时间戳，
跑完自己删。一次失败的运行会留下可辨认的残留，而不是一个说不清哪来的 catalog。

## 5. 顺带修掉的两处

**dev proxy 的端口写死了。** `proxy.conf.json` 里 target 是 `http://localhost:8080`，
而这台机器上 8080 是 nginx、8081 是 Nexus，服务端实际跑在 8088 —— `npm start` 之后
每个 `/v2` 请求都是 502，页面上没有任何解释，只有 devtools 里一行红字。

改成 `proxy.conf.js`（json 读不到环境变量），端口取 `GF_API_PORT`，默认仍是 8080：

```
GF_API_PORT=8088 npm start
```

实测通过：页面 200，`/v2/version` 正常代理回来。生产不需要这套 —— 同一个 jar 出页面和接口，
所以前端始终只用相对前缀。

**搜索页的提示语和实测结论不符。** 原来写的是 "Describe a picture and get the picture"，
但后端实测的结论是：描述画面（颜色、主体、构图）有效，用图上印的文字去搜无效 ——
缩略图缩到 224×224 之后那些字读不出来。改成：

- 模式提示：`Describe what is in a picture — a colour, a subject. Not the text printed on it.`
- 空状态：`... Pictures wants what a picture looks like.`

一句话的事，但它决定了第一次用的人会不会得出"这功能不行"的结论。
