# 2026-08-31 · frontend

前端从零建起来：Angular 21（signals）+ RxJS + Angular Material + Tailwind，绿白为主。

位置：`frontend/greenfinger-ui`。

---

## 1. 脚手架与技术栈

```
ng new greenfinger-ui --style=scss --ssr=false     # Angular 21.2，默认 zoneless
ng add @angular/material@21                        # M3 theming API（mat.theme）
npm i -D tailwindcss @tailwindcss/postcss postcss   # Tailwind 4
```

两处需要说明：

- **没有装 `@angular/animations`**。Angular 21 的 Material 不需要它，最初写的 `provideAnimationsAsync()` 会让构建报 `@angular/animations/browser` 解析不到 —— 直接去掉。
- **Tailwind 的 `@import` 放在单独的 `src/tailwind.css`**，不在 `styles.scss` 里。Tailwind 4 用 `@import` 引入，而 Sass 已弃用 `@import`，写在 scss 里会让每次构建都为一条不归我们改的规则报警告。`angular.json` 里排在 `styles.scss` 之前，Material 主题仍然后写后赢。

## 2. 主题：绿 + 白

`mat.theme()` 用 `mat.$green-palette` 作 primary、`$spring-green-palette` 作 tertiary，`color-scheme: light`。

页面上的绿只出现在**每页一块**：顶栏，和每页顶部那张 hero。其余全白。这样绿承载的是身份而不只是装饰。所有自定义色都取自 `--mat-sys-*`，不另起一套 hex —— 一个颜色只有一处定义。

界面按"不要太传统"来做：hero 上有缓慢漂移的高光，卡片网格代替表格，统计磁贴用毛玻璃，任务在跑时 hero 有一道缓慢扫过的光泽。都控制在"余光能察觉、正眼不干扰"的幅度。

## 3. 结构

```
src/app/
  core/         api.config / api.models / api.service / auth.service
                auth.interceptor / auth.guard / notify.service
  shared/       confirm-dialog
  pages/        login / catalogs / catalog-edit / monitor / search / about
  app.ts        外壳：顶栏 + 侧栏；登录页故意在外壳之外
```

路由全部 `loadComponent` 懒加载：未登录的访客只该拿到登录页，让他下载一个可能永远打不开的 catalog 编辑器是白付流量。

## 4. 几个真正做过决定的地方

**token 存 localStorage，但每次启动都问 `/me`。**
存是为了刷新页面不把人从正在看的爬取任务上踢下来；问是因为 token 可能已被别处登出或被服务重启作废 —— 信 localStorage 会渲染出一个"看着已登录、每个请求都失败"的壳。`provideAppInitializer` 里等它有结果，否则路由守卫会先跑，任何页面刷新都会先弹去登录页再弹回来。

**401 的处理只有一处，403 不动 session。**
401 = token 没了（过期，或另一个标签页登出了），拦截器清 session 跳登录页。403 = "你只能读"，是一个答案而不是坏掉的会话，页面自己说明就好。登录接口本身的 401 也不跳转 —— 那是密码错了，该留在表单上。

**列表页只在真有任务时轮询。**
`/crawl/status` 一次拿全部，三秒一次；`anyRunning()` 变 false 就停。爬取以秒计数、常跑几小时，轮询一个小接口比 socket 省掉一整类重连处理；但一屏都是已完成的任务时不该继续每三秒发一次请求。

**删除版本只在 Monitor 页，且强制先 dry run。**
列表页是快速操作的地方。不可逆的操作放在得专门点进去的页面上，先出报告、再确认。

**搜索三种模式做成一个框加模式切换。**
词 / 语义 / 图片是三个存储上的三种查询，不是一个查询加过滤条件。做成分段控件是为了让它成为操作者能做的选择，而不是藏在后端的决定。分页走 cursor，绕开 ES 一万条上限。

**编辑表单留空而不是预填。**
服务端能从一个 url 补出名字、start url、路径模式和全部上限。在表单里显示这些"猜出来的值"，等于让操作者对他从没选过的数字负责。高级项默认折叠：第一个 catalog 就是一个 url 加一次保存。

**版本号问服务端要。**
`GET /v2/version`，不写死在页面里，徽章不会比它标注的构建活得更久。

## 5. logo 与图标

`public/DefaultLogo.png` 是白底、**无透明通道**的 3:1 字标（里面那层棋盘格是画上去的，不是 alpha）。直接放到绿色顶栏上会是一个白方块。

`tools/make-icons.mjs`（`npm run icons`）：

1. 把近白像素抠成透明，带一段软边，保留字形的抗锯齿；
2. 输出 `logo.png`（裁到自身墨迹、缩到 900px 宽 —— 登录页最多显示 270 css px，3 倍屏也够，体积从 853KB 降到 120KB）；
3. **按"第一个空列"自动切出左侧那枚带叶子的 G** 做浏览器图标 —— 先按 1/3 宽度猜，把 "greenfinger" 的 g 带进来了；按列扫描 alpha 才切得准（实测切在 x=568/2172）；
4. 生成 `favicon.ico`（16/32/64 三档）、`icon-192/512.png`、`apple-touch-icon.png`（iOS 会把透明图标合成到黑底上，所以这一张单独垫白）。

字标在绿底上（顶栏、about hero）用 `filter: brightness(0) invert(1)` 反白 —— 它自带的渐变末端接近黑色。登录页是白底，用原色。

## 6. 联调

- 开发：`proxy.conf.json` 把 `/v2` 代理到 `:8080`，前端始终用相对前缀，生产同源，没有 host 要配、没有 environment 文件会写错。
- 生产：`npm run build:deploy` 把产物拷到 `deploy/static/`，`greenfinger-api.jar` 一个进程同时提供页面和接口。

## 7. 测试

vitest，20 个用例全绿：

- `auth.service.spec` —— 登录、角色、restore 只信 `/me`、token 被吊销后清干净、登出失败也要本地登出
- `auth.interceptor.spec` —— 带 token、登录请求不带、401 清 session 跳转、登录接口的 401 不跳转、403 保留 session
- `api.service.spec` —— 信封不外泄、`success:false` 抛错、cursor 用重复参数（它的分量可能含逗号）、删除默认 dry run
- `app.spec` —— 未登录没有外壳、登录后有、SUPPORT 看不到 New catalog、版本号来自服务端

## 8. 图片搜索显示真图

服务端加了 `GET /v2/image?path=`（从 blob store 取归档的那份字节），前端图库不再画占位图标，
直接 `<img>`。`object-fit: contain` 而不是 `cover` —— 爬下来的图什么比例都有，
裁到统一网格会把搜索真正匹配到的东西裁掉。

- 加载失败（版本被删过，向量还指着已经没有的文件）就回落成占位图标，不弹消息：那是正常状态。
- `loading="lazy"`：一屏 24 张。
- 说明区显示 alt，并给两个链接：所在页面，以及"see it in place"（图片在站点上的原地址，
  来自 payload 新增的 `imageUrl`）。
