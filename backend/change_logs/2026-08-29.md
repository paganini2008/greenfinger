## 一、今天做了什么

把 Greenfinger 从 **Spring Boot 2.7.18 + doodler** 重构为 **Spring Boot 4.1.1 + JDK 17** 的单机版，
新代码全部在 `backend/`，老代码归档到仓库根的 `history/`。

### 模块结构

```
backend/
├── greenfinger-core                 引擎 + 六大可插拔组件 + frontier/registry/semaphore
├── greenfinger-output               三条输出路径 + 两个 blob 存储 + 两个向量库 + 三个 embedding
├── greenfinger-record               可选 JPA 全量记录（catalog 与 resource 同库）
├── greenfinger-spring-boot-starter  自动装配 + CrawlerLauncher + ManifestReplayer + CatalogAdminService
├── greenfinger-cli                  spring-shell 命令 + 自研终端表格/进度渲染
└── greenfinger/bin/                 发布产物：run.sh + greenfinger.jar + config/
```

### 相对 1.x 的新增能力

| 能力 | 说明 |
|---|---|
| **图片抓取** | `<img>` / `srcset`·`<picture>` / `og:image`，按尺寸·MIME·字节数过滤，内容 sha256 跨页去重 |
| **三条输出路径** | 本地文件 / Elasticsearch / 向量库，每次抓取只启用一条 |
| **内容去重** | 在 URL 去重之外新增第二道，sha256 精确或 simhash 近似 |
| **断点续爬** | 持久化 frontier，**不依赖数据库** |
| **replay** | 本地抓完可重放进 ES 或向量库，**不重爬站点** |
| **数据库可选** | 不装任何东西也能跑；开了才写全量记录 |

## 二、必读：改动前要知道的事

这七条每一条都对应一次真实故障，改相关代码前务必先看。

1. **ES 必须走原生 REST，不要换成官方 Java 客户端。**
   Fred 环境是 ES **8.15.0**，而官方客户端最新是 9.x —— 它会因主版本兼容头**直接拒绝连接**。
   REST 的 index/bulk/search 在 7/8/9 之间稳定。同理 Qdrant / Weaviate / OpenAI 都走
   `RestJsonClient`（JDK HttpClient + Jackson）。

2. **URL 去重在「入队时」做，不能挪到「出队时」。**
   出队时去重会导致：限额触发 → 在途任务提前返回不写入 → 但 URL 已记进去重库 →
   resume 时被判"已见过"跳过 → **页面永久静默丢失**。
   现在 `CrawlerEngine.enqueue()` 是唯一的去重点，`handle()` 返回 boolean 表示
   「是否可以从 frontier 移除」，被限额打断的任务留在队里等 resume。
   种子 URL 例外：直接 `frontier.put()` 并补记去重，否则增量 `update` 永远进不了入口页。

3. **枚举字段不能直接映射成 JPA 实体字段。**
   Hibernate 7 会为枚举列生成 `check (col in (...))`，该约束在 H2 2.x 上**拒绝一切非空值**
   （实测 `counting_type=0`、`output_type='local'` 都被拒）。
   `Catalog` 里 `countingTypeValue`(Integer) / `outputTypeValue`(String) 是普通列，
   枚举通过 `@Transient` 访问器暴露，Jackson 用 `@JsonProperty` 保持外部形态不变。
   **别为了"优雅"改回 `@Enumerated` 或 `@Convert`。**

4. **OkHttp 5 要依赖 `okhttp-jvm`，不是 `okhttp`。**
   后者是 Kotlin 多平台的元数据壳（767 字节），Maven 解析不出变体，MinIO 编译期和运行期都会挂。

5. **CLI 有两条执行路径，逻辑必须放在共用处。**
   `@Command` 注解方法（交互模式）和 `CrawlCommands.dispatch()`（一行命令模式）。
   `--config` 文件加载曾经只写在注解方法里 → 命令行模式下静默失效。现在统一在 `run()` 里加载。
   短参数映射也要同步维护 `CommandLine.expand()` 与 `@Option(shortName=...)`。

6. **`DashboardRenderer.lineCount()` 必须从表格推导，不能硬编码。**
   它决定 ANSI 原地重绘往回移动多少行，数字错了实时面板就撕裂。

7. **默认 catalog 名用「域名中间段」，靠子域目录区分同域站点。**
   `books.` 和 `quotes.toscrape.com` 都叫 `toscrape`，输出落在
   `toscrape/books.toscrape.com/` 和 `toscrape/quotes.toscrape.com/`，互不干扰。
   曾经用完整主机名做 catalog 名，导致目录变成 `books.toscrape.com/books.toscrape.com/` 双层重复。

## 三、关键设计决策（及为什么）

- **续爬用持久化 frontier，不用 1.x 的「从最近一条 URL 继续」。**
  后者的问题是：爬取是图遍历，"最后落库的那条"和"还没爬的那些"无关，中断时队列里积压的
  URL 全部丢失；并发下那条记录基本随机。对齐 Scrapy JOBDIR / Nutch CrawlDb / Heritrix。
  副作用是**不需要数据库也能续爬**。
- **`resume` 与 `update` 是两个不同功能**：前者接着没爬完的队列；后者站点已爬完、回头捡新增。
- **不做 PageRank。** 作为排序信号它已不是主流（ES 走 BM25、向量库走相似度）；
  作为调度信号，流式爬虫拿不到完整链接图。若要提升有限额抓取的质量，
  应加优先级 frontier（深度/入链数/OPIC），`CrawlFrontier` 是接口，随时可插。
- **Faiss 去掉换 Weaviate** —— Faiss 没有维护良好的 Java 绑定。
- **配置全部外置**在 `backend/greenfinger/bin/config/`，jar 里不打包任何 yml；
  默认值的唯一来源是 `@ConfigurationProperties` 类。
- **catalog 存储三档**：`memory`（直接跑不落文件）/ `file`（默认，catalogs.json）/
  `jpa`（配了数据库时自动接管，catalog 与 resource 同库）。
- **自动任务/调度不搬**，Fred 说外置，后面再接入。所以 1.x 的 `WebCrawlerJob`、
  `ChannelSwitcherJob`、`CatalogDelayQueue` 都没迁移。

## 四、表结构变更（Fred 已逐条批准）

以 1.x 的 `db/crawler.sql` 为基准：

- `crawler_catalog`：`interval` → `fetch_interval`（INTERVAL 是保留字，MySQL 上会语法错）；
  `indexed` → `output_type`；新增 `index_version`/`last_indexed`（从 catalog_index 合并）、
  `record_enabled`、`image_enabled`
- `crawler_catalog_index`：**整表删除**，合并进主表，版本语义不变
- `crawler_resource`：新增 `content_text`、`content_hash`、`depth`、`referer`；补主键与索引
- `crawler_resource_image`：**新表**，图片记录

### 顺手修掉的 1.x 缺陷

`RocksDbUrlPathFilter.destroy()` 删整个数据库目录（导致无法续爬）· 同处吞异常后返回"已存在"
（一次 IO 错误静默丢弃整站）· `StatefulExtractor.setExtraCookies` 写成 `coookies.addAll(coookies)`
（自己加自己，登录 cookie 永远丢失）· 强制 UTF-8 解码（GBK 页面乱码）· 深度靠数 URL 斜杠估算 ·
Selenium 硬编码 Windows 绝对路径
